# P12.8 — p95 do `atlas-web` implantado

Medido pelo mantenedor no `dev` (App `atlas-web`, warehouse Serverless Starter) com
`scripts/measure_web_p95.py`, logo depois do primeiro `bundle run atlas_web`, com o cache de API frio
para municípios. Cada amostra é a 1ª chamada de `/api/map/municipality` por (UF, medida): 27 UFs ×
5 medidas (`gross_revenue`, `recharge_count`, `avg_ticket`, `active_pos`, `mom_change`), mês 2026-10.

| endpoint | n | mín ms | p50 ms | p95 ms | máx ms |
|---|---|---|---|---|---|
| /api/map/municipality | 135 | 931 | 1038 | 1457 | 3930 |

**Critério (SPEC-007 §6): p95 < 3 s. Atendido (1.457 ms).** Health: `healthy`, warehouse `RUNNING`.

## Leitura
- O ADR-0022 (conexão reaproveitada) se confirma no App: sem o Lakebase, a latência de API fica em ~1 s.
  O gatilho de reabrir o Lakebase (p95 > 3 s) não foi acionado.
- O p50 (1 s) é maior que o da conexão reaproveitada medida de fora (~345 ms): cada amostra é uma
  consulta nova por (UF, medida), e as primeiras de cada thread abrem a conexão. O máximo de 3.930 ms
  é uma amostra isolada (acima do limite, mas fora do p95).

## O que não foi medido
- A rede do navegador, o JSON de geometria (`geo/mun/<UF>.json`) e a renderização do SVG: a medição é a
  da API (SPEC-007 §6, nota).
- O 1º acesso depois do auto-stop de 24 h do App (o ADR-0022 pede para observar).
